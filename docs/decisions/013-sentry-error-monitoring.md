# 013 — Sentry로 에러 모니터링

- **Context**: MVP 운영 중 발생하는 unhandled exception을 빠르게 감지·재현해야 함. 자체 로그 수집 인프라 구축은 6주 일정 외. APM·Datadog·LogRocket 등 후보 중 (1) 무료 티어가 사용량 충분, (2) Next.js App Router 1급 지원, (3) source map upload + breadcrumb + replay까지 포함하는 솔루션이 필요.
- **Decision**: `@sentry/nextjs` v10 채택. `next.config.mjs`를 `withSentryConfig`로 래핑해 client/server/edge runtime 모두 자동 inject. 서버는 `src/instrumentation.ts`의 `register()`에서 runtime별로 `sentry.{server,edge}.config.ts` 동적 import. 클라이언트는 `sentry.client.config.ts`가 webpack에 의해 자동 번들. `tracesSampleRate: 0.1`로 무료 티어 (10K transactions/mo) 안에서 운영. `replaysSessionSampleRate: 0` + `replaysOnErrorSampleRate: 0.1`로 에러 발생 시에만 세션 replay 캡처. `tunnelRoute: '/monitoring'`으로 광고 차단기 우회. `src/app/global-error.tsx`로 React render 에러까지 커버. Production·Preview env에 `SENTRY_DSN`/`NEXT_PUBLIC_SENTRY_DSN`만 등록하면 끝.
- **Consequences**: 무료 티어 한도 (5K errors, 10K transactions/mo) 초과 시 다음 달까지 이벤트 누락 — 트래픽 증가 시 `tracesSampleRate` 추가 하향(0.05) 또는 유료 전환 검토. `withSentryConfig` 활성화로 First Load JS가 87 → 160 kB로 +73 kB 증가 (Sentry SDK). 클라이언트 번들 크기 민감하면 향후 lazy import 분리 가능. `SENTRY_AUTH_TOKEN` 미설정 시 source map 업로드는 자동 skip → CI/Vercel 빌드 실패 X, 단 Issues에 minified stack trace만 보임. 정식 운영 단계에서 Sentry CLI token 등록 필수. 검증 라우트 `/admin/sentry-test`에서 `?throw=server`/`?throw=client`로 양쪽 회로 점검 가능.
