# 015 — 안전운임 v2 (거리 기반, 연도별 스냅샷)

- **Context**: Stage 1의 `SafeRate` 모델은 (origin region, port, container) 기반 단일값이라 (1) 국토교통부고시 제2026-55호의 거리표와 paradigm이 다르고, (2) 가산방식 할증·대기료·공차·유가 연동을 표현할 수 없으며, (3) 연도별 갱신 흐름(매년 1월 새 고시)을 못 담는다. PortLink의 차별화 포인트인 "차주 안전운임 자동 검증"이 정확하지 않으면 신고 PDF·청구서가 법적 분쟁의 도화선이 된다.
- **Decision**: 신규 5모델로 v2 구축. (a) `SafeFreightYearlySnapshot`이 fiscalYear unique로 연도별 고시를 분리하고, (b) `SafeFreightRate`가 (snapshot, distanceKm 1~550, containerType, rateType) 매트릭스로 6,600행 보유, (c) `SurchargeRule`이 14종 할증을 snapshot 종속으로 박아 연도 변경 시에도 과거 룰 보존, (d) `FuelPriceAdjustment`가 분기별 ±50원 변동 조정, (e) `FreightCalculation`이 배차당 계산 결과 + ruleVersionSnapshot(JSON 풀 스냅샷)을 보관해 사후 분쟁 대비. 계산 엔진(`src/lib/safe-freight/calculator.ts`)은 별첨 코드를 그대로 사용 — 가산방식(1순위 100% + 2·3순위 50% + 4순위 무시), 중량물 자동, 대기료, 공차 회송, 유효기간 검증 모두 구현. 운임 3종(CONSIGNMENT/INTER_CARRIER/TRANSPORT) 중 INTER_CARRIER는 admin/CARRIER role에만 응답 노출. 기존 `SafeRate`는 deprecated 표기 + Stage 9에서 정리.
- **Consequences**: 신규 테이블이 6,600 row + 14 surcharge로 가벼우나, 매년 1월 새 고시 갱신 워크플로우가 강제됨([docs/safe-freight-yearly-update.md](../safe-freight-yearly-update.md) 참조). 컬럼 paradigm 차이로 Stage 1 SafeRate와 통합 불가능 — 두 시스템 병존 (deprecated 표기). 거리 측정은 네이버지도 Directions API 미연동 (Phase 2) 대신 사용자 입력 + "네이버지도에서 확인" 외부 링크. 미지급 신고 PDF는 면책 문구 3곳(머리/중간/꼬리) 박혀 PortLink 법적 책임 회피. 포워더 인라인 경고는 자동 알림 X, 체크박스 인지 동의만 (영업적 마찰 회피). `@react-pdf/renderer` 채택으로 First Load JS는 영향 없음(서버 전용 dynamic import) 단 cold start에 jsdelivr Pretendard CDN fetch 200ms 추가.
