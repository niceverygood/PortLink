# PortLink MVP 데모 시나리오

> 1회 시연에 약 12~15분. 운영 환경(`https://port-link-snowy.vercel.app`) 또는
> 도메인 연결 완료 시 `https://portlink.kr` 사용. 모든 계정은 1-Click 로그인 패널로 접근 가능
> (단 `SEED_PASSWORD` 환경변수가 설정된 환경에서만 노출됨).

## 0. 사전 준비 (5초)

- 브라우저 시크릿 창 1개 (담당자/관리자 화면)
- 모바일 시크릿 창 1개 (또는 데스크톱 + DevTools 모바일 뷰) — 차주용 PWA
- `/login`에 접속해 1-Click 로그인 패널이 노출되는지 확인

## 1. 담당자 — 배차 생성 (3분)

**계정**: `kim@hanjin-demo.kr` (포워더) — 1-Click "포워더" 버튼

| 단계 | 액션                                                 | 보여줄 포인트                                         |
| ---- | ---------------------------------------------------- | ----------------------------------------------------- |
| 1.1  | `/forwarder/dashboard` 진입                          | 네이비 톤 데스크톱 UI, 좌측 사이드바, 오늘의 배차 KPI |
| 1.2  | "신규 배차" 클릭 → `/forwarder/dispatch/new`         | 컨테이너 정보 + 픽업/하차 + 안전운임 자동 계산        |
| 1.3  | 컨테이너 번호 / 출발(부산항) / 도착(이천 ICD) 입력   | 안전운임 계산 결과가 실시간 표시 (KRW integer 보장)   |
| 1.4  | 운임을 안전운임 미달로 한 번 입력 → 경고 메시지 노출 | 정책 enforcement 시연                                 |
| 1.5  | 정상 운임으로 수정 → 등록                            | `/forwarder/dispatch/[id]` 상세 페이지로 자동 이동    |

## 2. 차주 — 배차 수락 (3분)

**계정**: `010-3000-0001` 또는 1-Click "D-0001" 버튼 (모바일 화면)

| 단계 | 액션                                                  | 보여줄 포인트                                        |
| ---- | ----------------------------------------------------- | ---------------------------------------------------- |
| 2.1  | `/driver/jobs` 진입                                   | 오렌지 톤 모바일 PWA, 큰 터치 영역, 일감 카드 리스트 |
| 2.2  | 1번에서 만든 배차 카드 탭                             | 거리·운임·경유지 한눈에                              |
| 2.3  | "수락" 버튼 → 즉시 Trip 생성 (Server Action)          | 200ms 안에 응답, optimistic UI                       |
| 2.4  | `/driver/trip/[id]` 진입                              | 단계별 버튼 (출발 → 픽업 → 하차 → 완료) + grace 안내 |
| 2.5  | "출발 보고" → "픽업 완료" → "하차 완료" → "운송 완료" | 각 상태 전환마다 timestamp 기록, 잘못된 순서면 막힘  |

## 3. 담당자 — Trip 모니터링 + 정산 (2분)

화면을 다시 담당자 창으로 전환.

| 단계 | 액션                                | 보여줄 포인트                                                         |
| ---- | ----------------------------------- | --------------------------------------------------------------------- |
| 3.1  | `/forwarder/dispatch/[id]` 새로고침 | 차주 상태 갱신, Trip 상태가 "운송 완료"로 표시                        |
| 3.2  | "청구서 다운로드" 클릭              | Stage 8 — 안전운송운임 기준 PDF 즉시 생성 (Pretendard 한글 풀 임베드) |
| 3.3  | `/forwarder/settlement` 진입        | 완료된 Trip이 정산 대기로 자동 enqueue (CLAUDE.md §7)                 |
| 3.4  | "프리뷰" 클릭 → 정산 명세 확인      | 운임 - 수수료 - 부가세 = 차주 수령액 (모두 KRW integer)               |

## 4. 차주 — 정산 확인 (1분)

차주 화면으로 전환.

| 단계 | 액션                         | 보여줄 포인트                                   |
| ---- | ---------------------------- | ----------------------------------------------- |
| 4.1  | `/driver/settlement` 진입    | 누적 정산액 + 이번 Trip 정산 entry 표시         |
| 4.2  | "이의 제기" 버튼 (있는 경우) | 분쟁 채널 시연 (CLAUDE.md §11 settlement-issue) |

## 5. 관리자 — 운영 백오피스 (2분)

**계정**: `admin@portlink.kr` — 1-Click "관리자" 버튼

| 단계 | 액션                | 보여줄 포인트                                      |
| ---- | ------------------- | -------------------------------------------------- |
| 5.1  | `/admin/dashboard`  | 전체 KPI (이번 주 배차/완료/이상 건수)             |
| 5.2  | `/admin/dispatches` | TanStack Table, 필터/정렬/페이지네이션, CSV export |
| 5.3  | `/admin/users`      | 가입 승인 대기 목록, 1-click 승인/반려             |
| 5.4  | `/admin/anomaly`    | 이상 거래 (장기 미수락 / 운임 outlier) 자동 검출   |

## 7. 마무리 메시지 (30초)

- **목표**: 담당자 스마트폰 없이도, 차주가 종이 없이도 배차 → 운송 → 정산까지 완결
- **차별점**: 안전운임 자동 계산·강제, 분쟁 채널 내장, KRW integer 일관성, 한국 사용자에 최적화된 단일 리전(ICN1)
- **차주 권리 안내 차별화**: **PortLink는 다른 주선사가 알려주지 않던 권리를 차주님께 알려드립니다.** 안전운임 §14 공차 보상 청구권을 자동 감지·안내하고 청구서 양식을 제공합니다 (자동 청구 X — 차주가 직접 결정).
- **다음 단계 (Phase 2)**: 멀티 운송사 정산 분배, OCR 기반 컨테이너 번호 인식, 실시간 위치 추적
